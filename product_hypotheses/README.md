## Постановка задачи

Аналитик интернет-сервиса (VPN), который построен по клиент-серверной архитектуре и продаётся по подписке на тарифы. Клиент — мобильное приложение для Android, iOS и Huawei. Команда сопровождения передала дамп серверной БД, структуру таблиц и логи клиентов по инцидентам.

Нужно сопоставить данные о клиентах и их действиях, сформулировать продуктовые гипотезы и проверить каждую на данных. Задание предлагает такие гипотезы:

1. Есть пользователи, которые заводят новый аккаунт ради повторного триала. Как их находить и какие косвенные признаки есть в данных?
2. Лимиты бесплатного тарифа (500 МБ в день, 15 ГБ в месяц) выбраны на глаз, а для расширения нужно смотреть рекламу. Какие объёмы оптимальны при реальном потреблении?
3. Сколько пользователи сидят на бесплатном тарифе до покупки? Всегда ли покупка идёт после триала и сколько покупают без него?
4. Какие паттерны поведения по логам инцидентов приводят к типовым ошибкам?

## Данные

Данные в репозиторий не входят: это выгрузка партнёра объёмом около 10 ГБ, в ней есть персональные данные. Скрипты ожидают папку `db` в той же структуре, в какой её выдал партнёр:

```
db/
├── db_structure/          # названия колонок и внешние ключи для каждой таблицы
├── users.csv, orders.csv, subscribe.csv, transactions.csv, devices.csv, ...
├── adv_view_history.csv   # просмотры рекламы за расширение лимита
├── user_connection_logs_02_26.csv … user_connection_logs_09_26.csv
└── logs/<user_id>/<архив>.zip   # клиентские логи (распакованный logs.zip)
```

В CSV нет строки заголовка, кроме `user_connection_logs_*`. Названия колонок скрипты берут из `db_structure`.

Что важно знать о сервисе (из данных):
- Тарифы: Basic (бесплатный), Lite ($4,49), Silver ($8,99), Gold ($12,49), Diamond ($21,99).
- Триал даётся на Lite: 3 дня за $1 (30 ₽), карта привязывается.
- Бесплатный лимит — 524 288 000 байт (500 МБ) в день. Каждый просмотр рекламы добавляет 200 МБ.

## Метод

| Гипотеза | Источники | Как проверялась |
| --- | --- | --- |
| 1. Повторные триалы | `orders`, `devices`, `saved_payment_methods`, `users` | Аккаунты с оплаченным триалом группируются по общему push-токену FCM, iOS-идентификатору устройства и маске карты. Ключ, на котором два и больше триальных аккаунта, означает повторный триал. Считается ритм между триалами, конверсия, доля гостевых аккаунтов. |
| 2. Лимиты бесплатного тарифа | клиентские логи (`TrafficLimitBloc`), `adv_view_history`, `user_connection_logs_*`, `orders` | Суточный расход трафика берётся из логов (отдельно дни с рекламой и без). Считается распределение просмотров рекламы в день и доля платящих в зависимости от интенсивности просмотров. Месячный лимит сравнивается с числом активных дней в месяц. |
| 3. Путь к покупке | `orders`, `users` | Первый оплаченный триал и первая полная оплата по каждому пользователю, сегменты сценариев, время от регистрации до первой покупки, автопродление после триала, повторные платежи. |
| 4. Паттерны ошибок | клиентские логи, `subscribe`, `user_connection_logs_09_26` | Каждая сессия приложения описывается признаками: ошибки API, DNS, тип сети, лимиты, начато ли подключение и удалось ли оно. Сравнивается доля неудачных подключений с признаком и без него, отслеживается динамика ошибки 400 по неделям. Результат сверяется с серверной активностью. |

Оговорки:
- Цифры по клиентским логам в этом описании получены на выборке: 167 архивов из 926, 144 пользователя, 10 061 сессия.
- Логи присылают пользователи, у которых возникли проблемы, поэтому доли ошибок в них завышены относительно всей аудитории. Почти все сессии — Android.
- Расход трафика есть только в логах новых версий приложения: 22 пользователя, 110 пользователе-дней. Это ориентир, а не оценка по всей базе.
- В `users.created_at` время на 3 часа впереди времени заказов. Скрипты это корректируют.

## Результаты

Полные таблицы — в [`results/summary.md`](results/summary.md) и CSV в папке `results/`.

| # | Гипотеза | Вердикт | Ключевые цифры |
| --- | --- | --- | --- |
| 1 | Аккаунты заводят заново ради триала | **подтверждена** | Не меньше 1 000 из 22 193 триальных аккаунтов (4,5%) делят устройство или карту. До 12 триалов на одно устройство. Самая частая пауза между триалами — 3–4 дня, ровно длина триала. |
| 2 | Лимиты 500 МБ / 15 ГБ неоптимальны | **частично** | В дни без рекламы медиана 95 МБ, 90% дней — до 274 МБ. Месячный лимит без рекламы недостижим: 90% бесплатных подключаются 8–15 дней в месяц. Кто смотрит 50+ роликов в день, платит в 3,11% случаев против 1,57% в среднем. |
| 3 | Пользователи долго сидят на бесплатном тарифе перед покупкой | **не подтверждена** | 60% платящих покупают в первый час после регистрации. 76% начинают с триала. После триала платят 56%, и 82% этих оплат — автосписание через 72–84 ч. Без триала купили 6 829 человек. Гостевые аккаунты не платят. |
| 4 | Типовые ошибки имеют повторяющиеся паттерны | **подтверждена** | HTTP 400 на `location/link` почти только у бесплатных (641 из 644 сессий). С ним подключение не удаётся в 40% случаев, без него — в 5%. Доля 400 выросла с 1–2% до 28% сессий за 14–27 сентября 2026 г. Бесплатная аудитория за день упала примерно с 92 до 72 тыс. |

### Предложения

1. **Ошибка 400** (срочно): по серверным логам разобрать, почему `api/v2/location/link?autoSelect=true` отвечает 400 бесплатному пулу. Вместо 400 отдавать понятную причину. Включить предупреждение о скором конце бесплатной сессии (сейчас выключено флагом).
2. **Повторные триалы**: выдавать триал один раз на push-токен, iOS-идентификатор и карту. Для Android передавать с клиента устойчивый идентификатор устройства.
3. **Лимиты** (A/B-тест): базовый лимит 300 МБ, потолок 10 просмотров рекламы (+2 ГБ) в день, при упоре в потолок — предложение Lite. Метрики: конверсия в оплату, доход от рекламы, отток бесплатных.
4. **Путь к покупке**: считать конверсию триала по второму платежу, а не по автосписанию. Проверить покупку из гостевого режима без полной регистрации.

## Как запустить

Нужен Python 3.10 или новее.

```bash
pip install -r requirements.txt
cd product_hypotheses/src
python run_all.py "C:/путь/к/папке/db"
```

Нужно около 4–5 ГБ оперативной памяти. На выборке из 167 архивов логов прогон шёл около 2 минут; на всех 926 архивах разбор логов займёт дольше, а цифры гипотез 2 и 4 немного уточнятся. Результаты появятся в `results/`. Каждую гипотезу можно запустить отдельно: `python h1_trial_abuse.py <db>`, и так же для `h2_free_limits.py`, `h3_purchase_path.py`, `h4_log_errors.py`.
